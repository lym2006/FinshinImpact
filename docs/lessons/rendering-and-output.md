# 图像、渲染与输出格式

**什么时候会撞上**：把文字渲染成图、合成表情包、决定消息用哪种格式发出、设计渲染失败的降级。

## Pillow 变形合成的方向容易记反

`Image.transform` 的 `QUAD` 传的是**源图的采样区**，结果一律铺满输出画布，而不是「把图贴到这四个点围成的位置」。想按目标四边形贴图要用 `PERSPECTIVE`，它要 8 个系数（9 个减掉一个自由度），`QUAD` 的 8 个坐标不能直接当它用。这个方向说反过一次，症状是变换结果跟预期完全无关。

## 别靠透明通道反推坐标

「把 alpha 反转取外接框」来自动推导模板槽位，实测直接失败：模板本身就是透明底，反转后整张图都算内容，外接框返回整幅（`0,0,100,100`）。透明 ≠ 空内容，透明底上照样可能画着东西。

调研过的一整批同类项目，没有一个实现坐标自动推导，全都要人工标注——这本身就是结论，别把它当成还没找到的技巧。要定位就显式标：用标记色（品红这类在素材里不出现的颜色）反查像素是可行的，但注意 `ImageDraw.rectangle` 画的框**含两端点**，外接框会比预期多 1 像素（标 `(20,30,80,90)` 得到 `(20,30,81,91)`），按它裁剪就偏。

## GIF 的两处省心写法

- 多帧合成用 `append_images=` 直接收内存里的图像列表，别先落盘再读回。一个 58 帧的量级省下 58 次写 + 58 次读。
- 逐帧透明要 `quantize()` 量化调色板并设 `disposal=2`（画完擦除），否则每帧的残留叠在一起，看起来像鬼影。这是 GIF 格式的限制，不是 Pillow 的 bug。

## 换库前先问装不装得上

`wand`（ImageMagick 绑定）在这类活上更顺手，但它要在用户机器上装外部二进制，与「包内自带 Python、离线首启」的发布形态冲突，因此不换。同理，在线模板/表情包 API 被否掉三条理由：第三方服务稳定性不可控、要把用户头像上传出去（隐私）、本项目的需求本地就能做。**凡是把本地能做的活搬上线，先过这三关。**

## 渲染失败要有明确的降级面

Markdown 转图失败时，输出退化成可读文本而不是丢掉内容。几条已经定下的口径值得连着记：

- 降级文件用 `.md` 后缀，命名带时间戳（形如 `回复_<时间戳>.md`），不附摘要——摘要本身是可能失败的那一环。
- 走文件发的消息，`caption` 一律留空。TG 与 QQ 对文件配文的处理不一致，填了反而触发平台侧改写。
- 遇到不支持的输出类型**抛明确异常**，不许静默丢弃。静默丢的表现是「用户发的东西没了」，比报错难查十倍。
- 渲染触发条件要从「会话级开关」下沉到「消息级判定」（**已定案、尚未重做**：会话级那个标记位与相关补丁已删，渲染入口待按消息引用重建）。会话级开关的语义是「这个会话要不要渲染」，实际要问的是「这一条要不要」，按会话记会让状态在长会话里漂移。

## 平台对文件大小与形式的接受度不同

字符画、小视频可以直接进聊天窗预览。超过某个体量必须走 `document` 发文件，否则平台会压缩或拒绝。实测过一个倒放音频，体积超了只能发文件。**输出格式的选择按平台上限判，不要按「看起来能不能发」判。**

## 重渲染要做成增量，别每次进程都重画

帮助图按菜单内容算一个摘要（展示顺序全行加说明文字），写进伴生的 `.digest` 文件。两者都在且与当前内容相符才命中，直接复用旧图。这样只读文案不重画，改了说明、加了开关、调了行序才会重画。每进程强制重画的写法在启动链上就是一笔白付的秒级开销。

摘要只用来做「内容变了没」的侦测。它不能兼任「文件在不在」的判据——那属存在性判定，见 [`deps-and-release.md`](deps-and-release.md) 里退役运行时指纹那段，同一个错法在两个场景各犯过一次。
