# 分层与依赖

**什么时候会撞上**：给一段代码或一个符号挑归宿、改依赖方向、加一层、动门面。

## 选层判据

一段代码要搬进某个包，同时满足三条才算数：在层链里位于它的消费方之下、它需要 import 的东西那个包允许 import、引导期要用到的话必须在身份码写入前可导入。少一条就是事后被契约判红。

实际吃过一回：引导期的装库工具想下沉，第一版落进层链最底下的那个包，理由是它是系统层、又是空门面。落完契约判红五条——最底层不许 import 领域层与样式层，而这几件工具正要用那两层的词表和文案。教训是**先跑契约再定归宿**，包名与目录起了改不动。

服务层是引导期零 Qt 工具目前唯一合格的归宿：它在界面层之下，允许向上引领域与样式，又能在身份码写入前导入。往其他层放都要破某一条——工具族被自家门面连坐冻结，领域层有零外部依赖契约，而给工具单独开一只根包没有任何判据支撑。

同理，插件要 import 的类型必须放服务层而不是适配层，放适配层就撞「插件不依赖适配层」那条契约。

给符号挑住户也有一套。先看谁是最低的引用者，符号必须住在引用它的最低那一层或更下面。再看它是领域事实还是展示外观，领域事实进领域层，展示令牌进样式层。类型和实例还要分工：门面只代发类型与实例化好的单例，裸类型定义留在子模块里不进门面。样式令牌这类东西的最低引用者是拼样式表的那个包，而样式层位于领域层之下，把它们挪进领域层立刻造出反向依赖。拼样式表用的那个类型反倒不进门面令牌表，因为令牌模块自己不用它。

## 门面与私有子包

界面层下面所有子包都以下划线私有，外部要取界面件只能走界面层门面。这里有条容易被误读的规矩：**只要有一个包外的消费者，符号就必须进门面表**，不能因为「就一家在用」让消费方去直连私有模块。内部扫描器把跨包访问下划线私有模块判硬性违规，一轮就能报出十几条。想守「门面最小导出」而绕开门面，最后还得老实进门面。

门面表里的路径只能指到子包门面，不能直连更深的私有模块。pyright 和测试都察觉不到，扫描器会判跨包私有访问。代价是取任意一个弹窗就会 eager 拉起整棵弹窗依赖树，同层内部件，认了。

eager 子包门面是要付钱的，引导期路过它就算进启动时间，实测一次门面转发能轻易带走几十毫秒。所以服务层的包门面一律只留 docstring 不做转发，消费方直连具体模块。

被 import 的名字不许带下划线：公开面是给别的包用的，私有性由「进不进门面」表达。`__all__` 只在非空的包 `__init__.py` 里写，`from . import _mod` 这种模块级引用豁免。

## 命名口径为什么这么定

三类后缀、词根贯通、标识集中到领域层，这些条文在 [`../coding-style.md`](../coding-style.md) 的「命名与门面导出」，这里只记它们各自防的是什么。

改名最容易漏的不是主属性名，是同一个概念散在形参和局部缩写里的残留。它不报错，只在下次搜索时让人找不全，所以类型检查与扫描器都不会替你把住。

同一个类型有两个入口就会改哪边都漏一条，所以跨模块复用的标识只许从一个地方 import，两级门面都不 re-export。反过来，插件私有的标识名留在插件模块内，不抬进领域层——那里只放跨模块的底层标识。

## 该不该加一层

中间层存在的判据是**它自己算出点什么**。主窗装配入口站得住，因为它算了「按钮键与控制器互为补集」。一层纯转发的接线站不住，那只是把调用点挪了个位置。想加「胶水」前先问这层有没有判断。

同理，一个只为把一族 `NewType` 分开放的单独文件属于虚假耦合——拆开反增导入，一族至少两个同族成员才配独立成文件。给适配层建一个空的基类包也被判为虚假耦合，没有共性行为就别建基类目录。

拆分触发线、下限、只拆不合与紧耦合豁免的条文见 [`../coding-style.md`](../coding-style.md) 的「拆分粒度」。数字不抄进本文：阈值一挪，抄来的那份就成死档。

## 两侧都要实现的接口放哪儿

- **容易错成**：代发平台要实现的那几份抽象接口留在本体侧，让适配器去 import 本体。
- **症状**：接口所在那层还得允许引第三方库，插件与业务侧想实现或消费接口就得伸手碰适配层，一条契约判红一片。
- **为什么**：接口是两边共同的下界，谁的上面都不许站。留在任一侧里，另一侧就必须向上引用。
- **建议动作**：单独一只零第三方依赖的接口包，两侧都向下依赖它，再用契约把「除适配层外不许引平台框架」钉死，靠契约而不是靠评审记着。
  - 这只包的存在理由就是它不许引任何东西，与上文「给工具开根包」不是同一判据，别互相当先例。
  - 接口独立不等于两侧断往来：适配器照旧向下用本体的通用件，挡的只是平台框架进本体，别把「互不引用」写成目标。
  - 适配器的自描述清单也走同一条路子：目录里交一份清单，装载侧只认清单里写的平台与版本，入口模块名由本体规定，加平台不改装载侧代码。

## 施工顺序与契约维护

自上而下改依赖方向会两头都验不到，实际用的顺序是自底向上——领域对象、DTO、契约接口、再往上，每层跑一遍 ruff、pyright、lint-imports。

契约随层渐进添加，别一上来给整层写全量豁免——那样等于没契约。层链改动要三处同步：根包清单、层链契约、专门契约，改完删缓存再跑。

`frozen=True` 只锁顶层字段，list 字段仍可原地 append，所以容器一律用 tuple。两个枚举数值撞车（权限档位与任务优先级都用了 0/10/50）时，只靠 docstring 分语义，别指望类型系统能拦住混用。容器差异（群与私聊）不进枚举，由命令矩阵按作用域声明。
