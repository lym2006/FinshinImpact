# 被否掉的方案

**什么时候会撞上**：想引入一个新依赖、新层、新机制，或者觉得「这里居然没做」的时候。下面记的是讨论过并明确不做的，附当时的理由。

**理由比结论重要**：条件变了（依赖变小、需求变硬、平台开放了新接口），结论可以重开，但要把这一条改掉再动代码，别当作从来没人想过。

## 依赖与运行时

- **MySQL 作存储**：要用户自备服务端，与「下载 zip 即用 + 启动器自动升级」的发布模式冲突。仓储接口留了可再加实现的位置，但没有读者之前不实现。
- **pydantic 作 DTO 载体**：需要打包 hook、冷启动变慢。项目本来就用 dataclass，DTO 结构简单，收益盖不过这两笔开销。
- **`tiktoken` / 官方 tokenizer 自己数 token**：分词只对某一家准，还要联网下载编码文件。判断上下文压力用平台返回的 `usage`。
- **`wand`（ImageMagick）做图像合成**：要在用户机器上装外部二进制，与内嵌 Python 的离线首启冲突。
- **多进程 / 多窗口各跑一个 bot**：三条硬约束。同一个 bot token 的 `getUpdates` 只许一个消费者，两个进程互抢会随机丢一半消息，这是服务端行为绕不过。WAL 只解决多读，写仍是全库单写者，多进程写同一个库文件会频繁 `database is locked`。配置文件只有一份，两个进程的热重载互相覆盖。要真做得改成每实例独立库文件 + 独立配置目录 + 带实例后缀的锁名，改动面大而收益小——单进程多 Adapter 已经覆盖「同时跑 TG 和 QQ」与「同时跑多个 TG bot」两个真实需求。
- **引导选完实例后 re-exec 重启进程**：会脱离启动器的进程树，升级与锁的语义都断。改成同进程内先引导，拿到身份码写入环境变量之后再 import 业务模块。
- **模块顶层导入 aiogram**：拖慢启动，还把框架依赖摊到所有层。改延迟导入。

## 分层与命名

- **`bot/` 目录改名 `runtime/`**：与包内嵌入式 Python 的运行目录同名，两个 `runtime` 一眼分不清，还有 3 处硬编码路径要跟着改。
- **空的 `adapters/base/` 子包**：里面没有代码，只为「以后可能放东西」占位，制造虚假耦合。有内容再建。
- **标识模块继续拆分**：拆完每个文件只剩两三个符号，读一处要跳三处，不抵成本。
- **`UnitOfWork` 事务接口**：整类删除。回滚后置交给启动器，bot 代码不持事务。启动清死行走一条 UPDATE 就够，不需要事务。
- **`AdapterCapability` + `supports()` 能力协商**：共享层没有任何代码路径靠它分支，能力申报只是实现的一份副本，会随改动漂移而无读者。平台差异由 Adapter 内部降级，降级形态写进各自的 docstring。
- **契约里加 `fetch_content`**：Telegram Bot API 没有按 id 取消息的接口，进契约就只能写一个永远抛异常的实现。改由入站事件携带被引用消息的文字。
- **QSS 拼接归界面层**：拼样式表是纯字符串活、0 Qt 依赖，归样式层的样式表包。界面层只负责把样式表接到控件上。
- **把 Telegram 专属的配置键拆成独立枚举**：代理段与代理模式留跨平台定义，只用注释标明目前仅 Telegram 用。面板隔离已由「按平台列段」的表做到，QQ 面板本来就取不到代理段。枚举成员拆不进两个文件，硬拆只是把一张表变成两张。
- **把字段键枚举并入配置键枚举**：两者值域重叠而语义面不同，合并后取错值不报错。`token` 干脆不是配置键，它在字段校验侧由 check 门面代发。
- **把值联合类型改名成 `XxxType`**：它是「值」的联合，与字段规格里的 `value_type` 撞概念，改名后两个词更难分。
- **用 dataclass 字段名当配置键**：字段规格要表达必填、候选值、取值范围、按平台拼页签四件事，dataclass 的字段元数据装不下，硬塞会变成两套真相。

## 配置与数据

- **用 token 的哈希当实例身份码**：token 一旦重新生成，实例目录就与既有数据、日志、人设彻底失联，用户看到的是「我的东西没了」。身份码可读、可手填、可备份，代价是用户可以自己造出难看的目录名，这个代价换得起。
- **给少量老实例写配置兼容迁移**：存量不超过三个实例，写迁移加验一轮的成本远高于让用户重填一次。见 [`config-and-data.md`](config-and-data.md)。
- **搬家时留旧路径的转发 shim**：shim 让漏改的一方静默走旧路径，两套对象并存。信号桥那种单例并存的后果是跨线程屏障失效、偶发不响应而不报错。删掉旧路径让漏改直接 ImportError 才是防线。
- **库里版本号比代码高时「尽力读」**：低版本代码读高版本结构会静默改坏数据。一律拒启并告诉用户备份在哪。

## 对话与行为

- **`/system` 二段式注入人设、`/change` 运行时改人设**：以 system 角色 append 进会话，与初始人设共存而不覆盖。多次注入无上限堆叠、没有删除入口。`/clear` 整体重置时连带蒸发——存续语义不成立。人设归配置文件与模板，由 git 管理、重启不丢。真要支持运行时改，正解是主体表的身份字段加组装 prompt 的单点注入。
- **摘要写进 system 角色位**：用户话术会升入指令位，等于把可被污染的内容放进权重最高的位置。
- **压缩时把旧 summary 并入新的**：同一段内容反复压缩会逐轮失真（摘要的摘要＝传话游戏），而且每轮都带上旧摘要会持续膨胀。既然已经超出一轮窗口，早期细节本来就该被遗忘。改为每轮独立压缩、新摘要直接覆盖旧的。
- **用 `max_tokens` 硬截输出**：截在半句话上比啰嗦更糟。长度靠人设软约束。
- **回复入库时限长**：半句话留在历史里，AI 回看自己的残缺发言会产生莫名其妙的行为。
- **靠提示词防冒充**：见 [`model-and-persona.md`](model-and-persona.md)，实测能被改名、能编造命令。权限判定必须在代码。
- **FSM 桥接到新架构**：全库已无 `FSMContext` / `StatesGroup`，多轮上下文靠内存字典。为 QQ 保留 FSM 只会把框架类型重新引回来。
- **把「这条命令收几个参数」写进 `plugin.toml`**：清单要长出 `args` 字段，帮助侧从此按字段解释每条命令的语法，业务命令的参数形态被搬进配置文件一处维护。改停在帮助插件里一份「认位置参数的命令」名单，代价是加带参命令要两处改（名单 + 命令自己），但清单只管可见性与开关，不掺语法。

- **「断满 N 秒才弹」、弹窗自动收起**：加一层延迟判据，换来的是「到底断没断」更难解释。有等待就给反馈优先。

## 界面

- **让界面层的哑控件包完全不读样式层**：设想是「哑控件够不到样式层」，前提从未成立——校验面板自己就拉调色板取色。建钮工厂收样式枚举比收裸串更有约束，用户明确要类型不要串。
- **全局自定义字体作用于 GUI**：会顶掉用户自己调好的系统字号。自定义字体只给输出内容（日志、帮助图、渲染图）用，面板一律系统默认。
- **按钮尺寸用 `min-width == max-width` 钉死**：只能钉住内容盒，祖先的 padding 仍加在外面。顶层窗的尺寸压不过布局 sizeHint。实测把窗口从 400×160 压塌成 345×146。「钉住了」不等于「复现了」，见 [`gui-and-styles.md`](gui-and-styles.md)。
- **引导期窗体留在启动包**：视图与引导职责混在一包里，Qt 出口收不干净。引导期窗体归界面层，启动包做到零 PySide6。
- **内联键盘配套的 `menu_action` 表**：键盘退役后没有消费者，表不建。
