# 配置、实例与落盘

**什么时候会撞上**：加配置项、动实例目录结构、写持久化与备份、做多个 bot 并存的东西。

## 身份码是这个项目唯一的隔离锚点

一个实例的身份码同时是三个东西：`instances/` 下的目录名、该目录里 `profile.json` 所属的实例、互斥体名的后缀。三处必须同源，改任何一处都要同步另两处，否则升级后老目录认领不到新逻辑，或者两个实例抢同一把锁。

用它做键而不用 token 的哈希，是实测权衡后的选择：token 重新生成即与既有数据目录失联，用户表现为「我这个人设和聊天记录没了」。身份码对用户可读、可手填、可备份。

## 新字段往哪放，取决于谁会重写它

实例备注名这类字段只进实例目录内的 `profile.json`，不进全局 `config.toml`。原因很实际：GUI 的设置面板按 schema 全量重写配置文件，落在配置里的新字段只要不在 schema 上，面板一保存就静默写丢。`profile.json` 是自描述文件，读写两侧都由持有它的代码负责，加字段不会被别的写入方抹掉。

同理，配置项改名要连 key 名一起想清楚：`profile.json` 里 token 的键名一改，全部既有实例立刻读不出 token，等于让用户重填一遍。这种键在 `system/profile_env.py` 里已提常量，改名的代价要在那里看得见。

## 隔离要三处一起隔，缺一处就串号

数据、日志、人设三样都要按实例分开。只分数据不分日志，GUI 的「查看日志」在两个实例间会指向同一份文件，排查时分不清是谁写的。只分日志不分人设，两个 bot 说同一段台词，用户以为配置串了。

反面教材有现成的：某开源框架的会话键由「用户 + 群 + 平台」三段拼成，不含机器人自身 id，于是同一个群里的两个机器人共享同一段上下文，互相接话。任何「按对象存状态」的设计，先问键里有没有把「哪个我」算进去。

## 配置结构只有一个源

一条配置项的键名、类型、必填、默认值、按平台归属，全部定义在 `core/domain/config/`（模型与规格在 `_models.py`，平台段表在 `_shared.py` 与按平台的文件里，拼表在 `_table.py`）。派生物都从它算：`config.toml` 的初值文本、界面 schema、读取侧的必填集合与缺键默认。**任何一处手写第二份，就会在下次加字段时漂移。**

界面可见的标题与说明文字不在这份源里，归 `skin/messages` 的配置文案类——结构定义属领域，展示文字属样式层，这条线在层链上是有契约卡的。

插件清单走同一个模式：标量字段的类型、必填与默认收进 `core/domain` 的清单字段表，两份 loader（工具层与引导层）共用。这样「引导期能读、运行期也能读」不必写两遍校验。

一个枚举做字典键时注意类型：`ProxyMode` 是 StrEnum，用它建的 dict 想按 `str` 查，得把变量注解成 `dict[str, ...]`，否则类型检查报参数类型不符。

## 少量存量数据不做兼容迁移

代理配置段早先是 `[basic]`，后来转成 Telegram 专属段。**老实例不做字段迁移、不写兼容代码**，让用户重填一次。判据是存量规模：实例数不超过三个，写兼容层加一轮测试的成本远高于让用户重填一次。存量大了再谈迁移，别默认「必须无损」。

## 会话键的前缀不能省

群号与用户 id 是不同来源的数字，号段会重叠（QQ 尤其明显）。键里带 `g`/`u` 前缀保证唯一。私聊场景让容器键等于用户键、同值双写，换来解析路径零分支——省下的那个 if 分支正是漏判的地方。

## 落盘位置要让升级替用户着想

要持久化的东西放 `instances/` 下，判据是启动器升级时保留哪些目录。`packaging/pack_spec.py` 的 `PRESERVE_NAMES` 是唯一口径，里面有 `instances`、`runtime`、`_internal`。放这儿的新目录升级零改动。放别处就要同步往保留清单里加一条，忘了就是升级删库。

反过来，插件依赖不需要用户手动重装：`services/env_setup/deps_manifest.py:77` 的 `catalog_digest` 把所有清单汇成一个摘要，与实例状态文件里记的上次比对（同文件 `:105` 的 `panel_needed`），不一致就提示补装。这个机制是加依赖不用重发安装包的唯一理由。

## schema 版本只许向下兼容，且要挡住向前

库里版本号比代码认识的高，一律拒绝启动并弹窗告诉用户备份在哪，不许「试试看能不能读」。低版本代码读高版本 schema 的后果是静默改坏数据，比启动失败难恢复得多。

备份份数有上限（三份），超出删最旧。删库重跑要幂等——清一半崩了不能留下让下次启动更坏的中间态。

## Windows 文件名不是通用键的载体

任何把外部 id 当缓存文件名一部分的地方，都要先净化：Windows 目录名不许冒号、星号、问号、反斜杠。跨平台的 temp 键尤其容易含冒号。清理循环如果按「文件名等于键」匹配，而写入时用了净化过的名字，就永远匹配不上，temp 目录只增不减且不报任何错——这类泄漏的表现只有磁盘占用，没有任何异常。
