# 界面与样式验证

**什么时候会撞上**：把内联样式串搬进样式表包、把裸 objectName 换成词表引用、改控件尺寸，或者需要证明「观感没变」。

## 等价性怎么证

两条实证方法，都比肉眼看截图可靠。

**逐字节比对**：把改动前的 `src` 用 `git archive HEAD src | tar -x -C <临时目录>` 解出来，两份树各跑同一个哈希脚本，取所有样式 builder 的输出串比 md5 或 sha256。字符串完全相等就不存在「渲染时才发现差一点」。

**离屏建窗取像素**：设 `QT_QPA_PLATFORM=offscreen` 加一个临时身份码，把窗口 `show()` 后 `processEvents()`，再用 `widget.grab().toImage()` 统计颜色分布。取众数而不是取中心点，按钮中心常命中文字本身。同法还能验模态（`isModal`）与实测窗体尺寸。

离屏脚本里构造的 QWidget 必须留一个 Python 引用，否则对象被回收，Shiboken 报「already deleted」，看起来像界面代码坏了。

离屏脚本本身的三条规矩：先把 QApplication 起起来再建任何窗（没起就建表现为崩溃而不是报错）。测模态窗要用定时器代点按钮，不然 `exec()` 卡死到超时被杀，症状是整窗无响应、没有任何断言失败。验证代码写成临时 `.py` 文件跑，别用 `python -` 接 here-string——它静默失败，脚本根本没执行而你以为验过了。

## QSS 的量法与坑

样式表里的 `min-width`/`max-width`/`min-height`/`max-height` 量的是**内容盒**，祖先规则里的 `padding` 加在它外面。旧写法渲染出的尺寸其实是全局令牌给的，窗内写死的那句在带父窗的真实调用链里从不生效。所以「删掉从不生效的死值」不等于「改变尺寸」，两件事要分开证。

反过来，为了做到零像素差而用 `min == max` 把尺寸钉死，按钮确实变成钉的值，窗口却会塌。那是**钉住了，不是复现了**。

控件级尺寸交给样式表时，值要引全局令牌并在窗内规则里写全，别指望祖先下渗——没有父窗就没有来源。悬停态两头同色的情形是窗内没声明 `:hover`，全局规则照常下渗，换样式承载点不影响它。

顶层窗口的尺寸压不过布局的 sizeHint，样式表钉不住，只能留在代码里 `setFixedSize`。需要高度随字号变的窗，用 `setFixedWidth` 加 `setFixedHeight(max(现值, sizeHint().height()))`。

**冒烟必须挂在带全局样式的父窗下。** 无父窗的条件下样式表恰好钉得住，给你假阳性。要和旧形态对照，`setFixedSize` 得在 `show()` 之前补，show 之后再补不会重算约束。

## 改承载点之前先比令牌值

别假设「同款弹窗即同款色」。有的确认弹窗底色与文字色和通用弹窗基件不同值，套公共基础件等于改外观。要合并两份重复样式串，先把两组令牌值逐条比完。

用户已经看顺眼的界面视为契约。动它的样式承载点必须自证等价：测出的像素差要写成具体比例，并交代差在哪一行哪一列、为什么会差，由用户认下额度才算过。

真机定稿过的组合效果（无边框 Tool 窗、两次 `processEvents` 定格、`WA_TransparentForMouseEvents` 点击穿透）改动前要先想清楚会看出什么差别。任务栏切回瞬间整面重绘白一下属固有代价，根治要拆导入步间泵，变慢又添竞态，重于收益。

离屏测不出 Win32 的合成行为，这类效果只能真机看。点击卡片后卡片消失也不是 bug：穿透点击落到桌面导致应用失活，Tool 窗按标准行为隐藏，切回即复显。

## 词表与门面

样式层的 objectName 词表是创建端与样式选择器两端的单源，新增控件名先加枚举成员再引用，别写裸串。

样式碎片不许出门面。按字段状态现贴的红黄串留在私有，外面通过零参工厂取一个成品串，门面维持「只发成品串与工厂」。把常量抬出门面图省事，等于给调用方开了就地拼串的口子，之前的重复就是这么长出来的。要改成窗级选择器得用动态属性加 `unpolish/polish`，属机制变更，得单独拍板。

## 常驻单例窗要连轮次状态一起判

- **容易错成**：进度窗是进程级唯一实例、收窗不销毁，起新轮时只问「现在有没有窗」，拿到的是上一轮定格在那儿的那只。
- **症状**：帧喂进去一个字也不显示，界面上像「点了没反应」，不报错也不崩，比崩难查。
- **为什么**：这类窗自认「结果已出就收下后续帧」，复用它的调用方不重新起轮就永远叫不醒它。
- **建议动作**：判定问「这一轮还在跑吗」，不在跑就走重新起轮那条——重置表格、复显、补播攒下的帧，别把帧交给定格窗。

## 没有伸缩件时提示标签会把行顶到窗中间

- **容易错成**：一竖排里放「提示语 + 表格 + 一行按钮」，去掉表格那条分支后以为剩下的照常贴在提示语下面。
- **症状**：按钮行掉到窗正中，提示语被拉成一大块空白（实测那只 QLabel 撑到 190 高），看着像布局整个错位。
- **为什么**：`QLabel` 纵向策略是 Preferred，槽位本身可伸缩。整排里没有 Expanding 件时，布局把全部富余空档摊给它。表格的 `QTableWidget` 纵向是 Expanding，它在场时空档就被它吃掉，所以另一条分支不出问题。
- **建议动作**：按分支补 `addStretch()`，且只在没有 Expanding 件的那条分支补——两边都补会把伸缩件抢走的那段空档也吃掉。离屏量 `geometry().y()` 与高度即可复现，不必截图肉眼看。

## 横向布局里的标签一开自动换行就自己挑了个窄宽

- **容易错成**：给一行短提示挂上自动换行，以为「行里有余量就不折」，哪怕同一行还排着两颗按钮和一个 `addStretch()`。
- **症状**：窗宽 900、提示只有十四个字，照样折成两行。同一份代码在无头平台跑出来是单行读数，看着像没毛病。
- **为什么**：开了自动换行的 `QLabel`，sizeHint 走「先自选一个窄宽、再按高度换宽」那条路，实测同一句从 168×16 变 120×32。
  - `QHBoxLayout` 只按 sizeHint 给宽，标签的最小宽度又塌到 24，富余空档全被 `addStretch()` 吃掉。
  - 同一只标签放进纵向布局会被拉满整行宽，所以顶部那句不折、只有按钮行那句折。
  - 差别不在文案长度，在它落在哪种布局里。
- **建议动作**：一行说得完的提示语不开自动换行，要留长句保险就让提示单独占一行，别叫它跟按钮抢横向宽度。
- **验证方法**：量折行必须用真机平台插件，`WA_DontShowOnScreen` 能不弹窗地拿到真实字号与缩放下的尺寸，无头给的单行读数不算证据。

## 只读富文本要铺一整行的底色

整行通宽底色带在只读比对视图上观感不如字色，下次再要整行底色先避开下面这三条死路。

- **容易错成**：给比对行加底色，以为富文本里写个带 `background-color` 的块、或者挂一条选区格式就能铺满一行。
- **症状**：色块只盖住文字那一段，行尾一截还是窗底色。改 `drawBackground` 覆写了根本不进，断点计数为 0。
- **为什么**：Qt 富文本不认块级元素的 `background-color`。选区格式在 PySide6 上只有游标与字符格式两栏，没有整行铺宽的那一位。文档底色走的也不是控件的 `drawBackground` 虚函数。
- **建议动作**：在 `paintEvent` 里先按每行的块边界矩形往视口 `fillRect`，再 `super().paintEvent`。顺序反了就成了色带压在字上。取像素验的时候左中右三点都要取，中间那点常命中字形本身。

## 会真崩的 Qt 坑

这几条不是风格问题，是会死锁或崩，别再靠手感复发。

- **模态窗显示期间禁改 `windowFlags`**。`setWindowFlags` 会让 Qt 销毁并重建窗口句柄：`exec()` 还没返回，旧模态循环永远等不到关闭信号，主线程死锁、整个界面冻住。表现是「点完成没反应然后全 UI 挂死」，不像标志位问题。**验证必须走真实的 `exec()` 路径**，离屏只构造不 exec 的冒烟根本测不出来。
- **`QCloseEvent`、`QAction` 属 `PySide6.QtGui`，不在 `QtCore`**。按名字归类去 import 会在运行期 ImportError，写代码时和类型检查都不一定拦得住，只有跑到那条分支才炸。事件类与动作类一律先查归属模块。
- **线程实例属性不许叫 `_stop`**。它覆盖 `Thread._stop()`，`join()` 时报 `'Event' object is not callable`。给线程对象挂同步事件要起个不撞基类的名字。
- **界面上计时器跳一格，等于主线程刚付掉一个同量级的原子同步块**。步间加事件泵救不了原子大块——往一个 5 秒的原子 import 里塞十个泵点仍然卡 5 秒。要修只能把活挪出主线程，别加泵。

## 模态、置顶、防误关是三件事

- **容易错成**：想让弹窗压在自家窗口上面，就顺手挂全局置顶。
- **症状**：置顶窗盖住聊天软件与截图工具，还关不掉，用户第一反应是「莫名其妙的窗」。
- **为什么**：模态只管"输入进不去别的窗"，置顶管"跨应用压在最上"，防误关靠的是摘掉标题栏的关闭钮。三者互不替代，而全局置顶是系统级特权，代价是抢走别人家的屏幕。
- **建议动作**：自家窗之间的先后靠"显示时上浮到本程序最前"就够了，跨应用一律不置顶。撤掉置顶后，原来靠置顶维持的相对次序要逐个窗重新看一眼——两个窗会同时出现的场景，得由"同一时间只允许出现一个"这类规则接管，别再加第二次置顶。
  - 拦输入的范围按"谁调出它"取，别无脑锁全程序。锁全程序会顺手把还在干活的进度窗一起锁死——那种窗只有按钮一个出口，被盖住又点不动就成了死窗。只锁调出它的那只，语义照样是"不许同时改其他内容"，却不误伤旁边的窗。真要锁全程序的只剩"退出整个程序"这一类。
  - 让位判据要认得出"我跟着的那只窗"：一旦那只窗自己也升级成模态窗，"有模态窗开着就让位"会把它自己算进去，浮顶从此自锁，表现为"有时候不浮"。
  - 自家两窗的先后有一条系统级关系可用：A 挂成 B 的跟随窗。光靠它不够——用户真机反馈，一只窗大一只窗小时，点到大的那一下仍把小的压了下去。要常驻在上面得再盯住被跟窗的激活事件补一次上浮。「窗已经显示时改跟随关系不当场生效」是按现象推的，未证实。要常驻其上的正解是跟随关系加一条盯被跟窗激活事件的补上浮，两者已收在同一个公共件里，改完仍要真机复验。
  - 上浮钩子得有人引用：事件过滤器没人持有就会被回收，挂钩随之悬空。被跟窗换人要撤旧挂新，同一只窗不叠第二层。
  - 补上浮只排先后，别连带抢焦点：提顶写成 `raise` 再加 `activateWindow`，用户点一下向导就被夺走输入焦点，肉眼是一片闪烁——真机反馈过第二次。
  - 重挂时按单一轮次名筛窗必漏：同一只窗还能跑另一轮，那轮的结论就被刚开出来的面板压住。筛"有没有可见窗"，不筛"是哪一轮"。
- **未实测**：模态拦输入期间，点到自家另一个窗的那一下会不会被系统吞掉。想靠"点自家窗就把弹窗提顶"找回被别的程序盖住的弹窗，可行的触发条件应是"程序重新拿到焦点"，不是"点到某个窗"。

## 只能真机验的部分

无头环境测不到下面这些，改到对应路径时得在桌面逐个窗口肉眼过：

- 通用窗壳（提示、等待、确认类）的渲染与模态、转圈启停与键盘焦点，启动提示卡的点击不白屏、强关后进程干净退出。
- 浮顶与拦输入：常驻结果窗压向导的次序与焦点、面板分档锁主窗的实际拦法、断连弹窗的抑制与补弹、各处逐秒计时的显示。
- 输出与比对排版：打开日志目录、装库子进程的流式输出、任务栏图标分组、两栏比对窗的折叠展开与同进退滚动、滚动手感、二次确认单行不折。

⚠️ 后台跑 `python -m bootstrap` 会立刻退出（退出码 0、日志空）——Qt 事件循环在无显示、无交互的后台不驻留。这类复验只能人在桌面做。

## GUI 文案与日志的对齐

面板图标按头部文字命中，文字里含「重连」字样的其它行会抢标。改日志行文案要连命中规则一起验。

日志格式串的列宽是硬约束：`%(levelname)-5s` 按五字符定死，塞一个六字母的自定义级别进来会把整列推歪。要加级别先量列宽。面板只用 DEBUG/INFO/ERROR 三档就是这个约束的结果，它已钉进编码规范。扫描器管不到这一条，靠评审守。

日志头部按全角冒号切，切不到再按半角冒号切。所以正文里出现半角冒号的时长串（`00:03`）会截断头部，让图标命中变味。日志里放时长用自然语言短串（`1 分 05 秒`），`MM:SS` 只给弹窗。

同一条分支既弹窗又打日志属重复通知，**日志直接删，不降 debug 留着**。反过来，没人认领的分支（落盘失败、装填退到模板、正文为空）必须留在 info，那是用户唯一的知情渠道。判据就一条：这一条有没有窗，有窗删日志，无窗升 info。

给用户的提示文案里不许出现「指纹」「哈希」「缓存」这类内部词，也不许出现控件与流程名。要交代来源就填调用方传来的来源词，窗只管排版不管语义。

## 控件该抽到哪一层

遇到「某控件族要不要抽公共件」这类**范围问题**，默认一路按四件套做到底，不用停下来逐次确认：枚举（单源标识串）→ 工厂 → 样式（QSS 引枚举、令牌归样式层）→ 文案（界面可见串进文案层）。

两类要主动停下标注，它们不算「抽多少」：

- **语义不同的控件不硬并**。右键菜单 `QMenu`（弹命令）与 `QComboBox`（选值）不并。工具栏按钮名是行为 id 而不是视觉样式名，不并进样式枚举。
- **撞反过度设计红线的不做**。业务窗专用件不当通用件。只有「一处设置 + 一处 QSS」的私有 objectName 不套全局枚举。各窗独有的布局私有方法不抽。曾经的下拉菜单自定义类、单次使用的样式壳都在此列。

自定义字体只供帮助图与仪表盘这类需要排版一致的输出面，面板控件一律用系统默认字体。用全局字体覆盖界面会顶掉用户自己调好的字号，属倒退。

## 只读富文本里的链接

`setMarkdown` 喂 GitHub 生成的正文时，裸链接会在版本号的小数点处被截断。

- 带版本号小数点的裸比较链接只有前半段进 `<a>`，后半段成普通文本。
- 截断后的地址在 GitHub 上是合法 URL，点开落到错误的对比页。
- 尖括号形式不截断，`(?<![(<])(https?://\S+)` 一条替换即可，注意别把 `[文字](url)` 里的圆括号链接也包进去。

`QTextEdit` 上没有链接信号，`anchorClicked` 与 `openExternalLinks` 都只在 `QTextBrowser` 上。

- 只读视图要用 `QTextBrowser`，并显式 `setOpenExternalLinks(True)`——该开关默认 False 会去 Qt 内部找锚点，点开报找不到。
- QSS 的类型选择器认子类，原先那条 `QTextEdit#名字` 不用改。
- 底色要拿离屏取 `palette().color(QPalette.Base)` 与令牌比一次，别凭记忆。

## 用户说「歪」先按截图反算，别照着话挪像素

- **容易错成**：反馈写着「往右下偏」，就把控件往左上挪几个像素，再要一张截图确认。
- **症状**：连着两轮挪完还是歪，而离屏量出来的左边缘与行心本来就对得上。
- **为什么**：观感上的歪常常是两块尺寸不等，不是位置没对齐，按方向挪像素动的是本来就对的那一项。截图还带一层显示缩放，直接数截图上的像素会把偏差放大一倍看。
- **建议动作**：先定倍数，用同一行里已知高度的件去除截图上对应的行距，量出这张图是几倍，再把坐标换算回件内。然后只比三件事：左边缘差、行心差、块与参照物的尺寸差。
  - 找实心色块要用「同一行内连续若干像素同色」的判据。子像素抗锯齿会把正文文字的边缘染成目标色，单点取色在文字行上假报命中。
  - 改控件状态（勾选、悬停）必须在取图之前。未勾选的描边色浅，墨迹阈值找不到，量出来像那块根本不存在。
  - 自绘件靠负外边距去跟邻件同心，会被自家 widget 矩形裁掉，做不出同心。真要同心只能动那只全应用共用的基件，属机制变更。

## 下拉菜单里按项换样式，属性选择器那条根本不跑

- **容易错成**：给某项动作对象挂一个自定义属性，再在样式层写「菜单项[属性=值]{ 颜色 }」，以为这一项就会变色。另一条是把富文本标签直接写进菜单项文字。
- **症状**：整张菜单看不出差别，红字那条从未生效。富文本那项把 `<span ...>` 原样显示成字面。更糟的是这条断言可能已经写进发布账，久了没人再看屏。
- **为什么**：样式表的属性选择器只对「控件」生效，而菜单项不是控件，它由菜单自己代画，挂在动作对象上的自定义属性不参与选择器匹配。部分语言绑定也没把逐项前景色接口暴露出来，富文本在菜单项上同样不被解析。
- **建议动作**：要按项换样式，就把那一项换成承载控件——给该项设一个默认控件（一只带对象名的标签），颜色与内边距都在样式层按那个对象名给。
  - 代价要当场量：这一行不再有原生的悬停底色，但鼠标点它仍能触发动作，两件事分别验，别由一条推另一条。
  - 更省的路是别动载体：用图标或文案前缀做警示，把防误操作交给二次确认，颜色只是提示不是护栏。
  - 拿掉不生效的机制要一起拿掉：属性选择器的样式规则与挂属性的那行代码同批删，留着就是假护栏。
