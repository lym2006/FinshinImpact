# 界面与样式验证

**什么时候会撞上**：把内联样式串搬进样式表包、把裸 objectName 换成词表引用、改控件尺寸，或者需要证明「观感没变」。

## 等价性怎么证

两条实证方法，都比肉眼看截图可靠。

**逐字节比对**：把改动前的 `src` 用 `git archive HEAD src | tar -x -C <临时目录>` 解出来，两份树各跑同一个哈希脚本，取所有样式 builder 的输出串比 md5 或 sha256。字符串完全相等就不存在「渲染时才发现差一点」。这条方法的产物是一个哈希和一个字符数，例如引导窗样式改前后同为 3933 个字符、md5 相同。

**离屏建窗取像素**：设 `QT_QPA_PLATFORM=offscreen` 加一个临时身份码，把窗口 `show()` 后 `processEvents()`，再用 `widget.grab().toImage()` 统计颜色分布。取众数而不是取中心点，按钮中心常命中文字本身。同法还能验模态（`isModal`）与实测窗体尺寸（某轮断连窗量到 340×192）。

离屏脚本里构造的 QWidget 必须留一个 Python 引用，否则对象被回收，Shiboken 报「already deleted」，看起来像界面代码坏了。

离屏脚本本身的三条规矩：先把 QApplication 起起来再建任何窗（没起就建表现为崩溃而不是报错）。测模态窗要用定时器代点按钮，不然 `exec()` 卡死到超时被杀，症状是整窗无响应、没有任何断言失败。验证代码写成临时 `.py` 文件跑，别用 `python -` 接 here-string——它静默失败，脚本根本没执行而你以为验过了。

## QSS 的量法与坑

样式表里的 `min-width`/`max-width`/`min-height`/`max-height` 量的是**内容盒**，祖先规则里的 `padding` 加在它外面。旧写法渲染出 132×44 其实是全局令牌给的，窗内那句 `btn_height=35` 在带父窗的真实调用链里从不生效。所以「删掉从不生效的死值」不等于「改变尺寸」，两件事要分开证。

反过来，为了做到零像素差而用 `min == max` 把尺寸钉死，按钮确实变成钉的值，窗口却会塌（实测过窗口从 204 高塌成 192，另一轮从 400×160 塌成 345×146）。那是**钉住了，不是复现了**。

控件级尺寸交给样式表时，值要引全局令牌并在窗内规则里写全，别指望祖先下渗——没有父窗就没有来源。悬停态两头同色的情形是窗内没声明 `:hover`，全局规则照常下渗，换样式承载点不影响它。

顶层窗口的尺寸压不过布局的 sizeHint，样式表钉不住，只能留在代码里 `setFixedSize`。需要高度随字号变的窗，用 `setFixedWidth` 加 `setFixedHeight(max(现值, sizeHint().height()))`。

**冒烟必须挂在带全局样式的父窗下。** 无父窗的条件下样式表恰好钉得住，给你假阳性。要和旧形态对照，`setFixedSize` 得在 `show()` 之前补，show 之后再补不会重算约束。

## 改承载点之前先比令牌值

别假设「同款弹窗＝同款色」。退出确认窗的底色与文字色和通用弹窗基件不同值，套公共基础件等于改外观。要合并两份重复样式串，先把两组令牌值逐条比完。

用户已经看顺眼的界面视为契约。动它的样式承载点必须自证等价，测出的像素差要写成具体比例（例如差 3.64%，全部来自按钮行上移 4 个像素，而旧那 4 像素是控件撑破布局槽的溢出假象），由用户认下额度才算过。

## 词表与门面

样式层的 objectName 词表是创建端与样式选择器两端的单源，新增控件名先加枚举成员再引用，别写裸串。

样式碎片不许出门面。按字段状态现贴的红黄串留在私有，外面通过零参工厂取一个成品串，门面维持「只发成品串与工厂」。把常量抬出门面图省事，等于给调用方开了就地拼串的口子，之前的重复就是这么长出来的。要改成窗级选择器得用动态属性加 `unpolish/polish`，属机制变更，得单独拍板。

## 常驻单例窗要连轮次状态一起判

- **容易错成**：进度窗是进程级唯一实例、收窗不销毁，起新轮时只问「现在有没有窗」，拿到的是上一轮定格在那儿的那只。
- **症状**：帧喂进去一个字也不显示，界面上像「点了没反应」，不报错也不崩，比崩难查。
- **为什么**：这类窗自认「结果已出就收下后续帧」，复用它的调用方不重新起轮就永远叫不醒它。
- **建议动作**：判定问「这一轮还在跑吗」，不在跑就走重新起轮那条——重置表格、复显、补播攒下的帧，别把帧交给定格窗。

## 没有伸缩件时提示标签会把行顶到窗中间

- **容易错成**：一竖排里放「提示语 + 表格 + 一行按钮」，去掉表格那条分支后以为剩下的照常贴在提示语下面。
- **症状**：按钮行掉到窗正中，提示语被拉成一大块空白（实测那只 QLabel 撑到 190 高），看着像布局整个错位。
- **为什么**：`QLabel` 纵向策略是 Preferred，槽位本身可伸缩。整排里没有 Expanding 件时，布局把全部富余空档摊给它。表格的 `QTableWidget` 纵向是 Expanding，它在场时空档就被它吃掉，所以另一条分支不出问题。
- **建议动作**：按分支补 `addStretch()`，且只在没有 Expanding 件的那条分支补——两边都补会把伸缩件抢走的那段空档也吃掉。离屏量 `geometry().y()` 与高度即可复现，不必截图肉眼看。

## 会真崩的 Qt 坑

这几条不是风格问题，是会死锁或崩，别再靠手感复发。

- **模态窗显示期间禁改 `windowFlags`**。`setWindowFlags` 会让 Qt 销毁并重建窗口句柄：`exec()` 还没返回，旧模态循环永远等不到关闭信号，主线程死锁、整个界面冻住。表现是「点完成没反应然后全 UI 挂死」，不像标志位问题。**验证必须走真实的 `exec()` 路径**，离屏只构造不 exec 的冒烟根本测不出来。
- **`QCloseEvent`、`QAction` 属 `PySide6.QtGui`，不在 `QtCore`**。按名字归类去 import 会在运行期 ImportError，写代码时和类型检查都不一定拦得住，只有跑到那条分支才炸。事件类与动作类一律先查归属模块。
- **线程实例属性不许叫 `_stop`**。它覆盖 `Thread._stop()`，`join()` 时报 `'Event' object is not callable`。给线程对象挂同步事件要起个不撞基类的名字。
- **界面上计时器跳一格，等于主线程刚付掉一个同量级的原子同步块**。步间加事件泵救不了原子大块——往一个 5 秒的原子 import 里塞十个泵点仍然卡 5 秒。要修只能把活挪出主线程，别加泵。

## 用户认可的观感是契约

启动提示卡的窗型（无边框 Tool 窗）、两次 `processEvents` 定格、仅靠 `WA_TransparentForMouseEvents` 实现点击穿透，这三样合起来是用户肉眼验过的效果，改动前要先想清楚会看出什么差别。任务栏切回瞬间整面重绘白一下属固有代价，用户已接受。根治办法是拆导入步间泵，会变慢又添竞态，已拍板不做。

离屏测不出 Win32 的合成行为，这类效果只能真机看。点击卡片后卡片消失也不是 bug：穿透点击落到桌面导致应用失活，Tool 窗按标准行为隐藏，切回即复显。

## 只能真机验的部分

无头环境测不到下面这些，改到对应路径时得在桌面逐个窗口肉眼过：

- 三个通用壳（提示、等待、退出确认）的渲染与模态表现，等待窗转圈启停，退出窗的键盘焦点。
- 断连抑制：配置面板开着时跳过弹窗，关掉之后下一拍仍要补弹。
- 五处逐秒计时的显示（转圈、提示卡秒表、行计时、断连轮询、关闭流程的轮询与超时强退、通知重弹）。
- 打开日志目录、装库全链的子进程流式输出、任务栏图标分组。
- 人设预览与编辑两窗的排版，启动、重载、编辑、模板覆盖四处共用的两栏拍板窗（右栏主色并持默认焦点，标题栏与 Esc 都拦下，拍板后进二次确认），以及重载读到一致时那句提示。
- 提示卡点击不白屏、启动耗时数字落到个位数秒、用 Alt+F4 强关提示卡后进程干净退出。

⚠️ 后台跑 `python -m bootstrap` 会立刻退出（退出码 0、日志空）——Qt 事件循环在无显示、无交互的后台不驻留。这类复验只能人在桌面做。

## GUI 文案与日志的对齐

面板图标按头部文字命中，文字里含「重连」字样的其它行会抢标（「重连成功」当时就被「重连」抢走过一次）。改日志行文案要连命中规则一起验。

日志格式串的列宽是硬约束：`%(levelname)-5s` 按五字符定死，塞一个六字母的自定义级别进来会把整列推歪，当时为它新加级别的改动因此被撤。要加级别先量列宽。面板只用 DEBUG/INFO/ERROR 三档就是这个约束的结果，它已同时钉进编码规范与扫描器。

日志头部按全角冒号切，切不到再按半角冒号切。所以正文里出现半角冒号的时长串（`00:03`）会截断头部，让图标命中变味。日志里放时长用自然语言短串（`1 分 05 秒`），`MM:SS` 只给弹窗。

## 控件该抽到哪一层

遇到「某控件族要不要抽公共件」这类**范围问题**，默认一路按四件套做到底，不用停下来逐次确认：枚举（单源标识串）→ 工厂 → 样式（QSS 引枚举、令牌归样式层）→ 文案（界面可见串进文案层）。

两类要主动停下标注，它们不算「抽多少」：

- **语义不同的控件不硬并**。右键菜单 `QMenu`（弹命令）与 `QComboBox`（选值）不并。工具栏按钮名是行为 id 而不是视觉样式名，不并进样式枚举。
- **撞反过度设计红线的不做**。业务窗专用件不当通用件。只有「一处设置 + 一处 QSS」的私有 objectName 不套全局枚举。各窗独有的布局私有方法不抽。曾经的下拉菜单自定义类、单次使用的样式壳都在此列。

自定义字体只供日志图、帮助图与渲染输出这类需要排版一致的输出面，GUI 面板一律用系统默认字体。用全局字体覆盖界面会顶掉用户自己调好的字号，属倒退。

## 只读富文本里的链接

`setMarkdown` 喂 GitHub 生成的正文时，裸链接会在版本号的小数点处被截断：`compare/v1.0.0-alpha.3...v1.0.0-alpha.4` 只有前半段进 `<a>`，后半段成普通文本，而截断后的地址在 GitHub 上是合法 URL，点开落到错误的对比页。尖括号形式不截断，`(?<![(<])(https?://\S+)` 一条替换即可，注意别把 `[文字](url)` 里的圆括号链接也包进去。

`QTextEdit` 上没有链接信号，`anchorClicked` 与 `openExternalLinks` 都只在 `QTextBrowser` 上，所以只读视图要用后者并显式 `setOpenExternalLinks(True)`——它的默认值 False 会去 Qt 内部找锚点，点开报找不到。QSS 的类型选择器认子类，原先那条 `QTextEdit#名字` 不用改，但要用离屏取 `palette().color(QPalette.Base)` 与令牌比一次底色，别凭记忆。
