# 写作规范

代码结构与命名见 [代码规范](coding-style.md)。本文规定 docstring、注释、文档正文、提交与发版文案的写法。

## 指针写法

- 同一条判据只写在一处，别处只指向那一节，链接文字写目标节的标题原文，地址带锚点，如 [跑法](style-checker.md#跑法)。
- 同文件内指节写「节名」，要带链接就写 `#锚点`。
- 要留的理由写成指针，理由正文进 lessons。
- md 相对链接指向的文件与节必须当场存在。
- 规范正文写全路径与符号名、当场可 grep，不写行号与临时产物。
- docstring 与经验文写角色类别（「建钮处」「各窗 QSS 选择器」），不点名标识符、模块或文件路径。
- 经验文里第三方 API 的键名、命令行与工具名照写。
- 代码注释里的 `# 用：<路径>` 属有意单源指针，照常写。
- 发布文档不写内部待办、批次编号、对话过程与只在一台机器上成立的叙述，不链接不进版本库的目录。
- 旧版迁移按受众分工：用户要不要动手与步骤进 [README.md](../README.md)，逐项改法进 [development.md](development.md)，改了什么进 [CHANGELOG.md](../CHANGELOG.md)。
- 对每只子仓都成立的规矩与指路写主仓，只对某一只成立的才写它自己的 README。

## 中文措辞

以下写法适用于 docstring、代码注释与文档正文：

- 写人话，不自造术语与内部简称，要指什么就写那件事本身。
- 删修饰、比喻、连接性废话与口语尾巴，不堆书面腔也不刻意口语。
- 一个从句说得清就不加第二个，能删的限定词一律删。
- 不拿 `＝` 与 `=` 代替「就是」，代码与命令行里的语法照旧。
- 禁「前者/后者/此类」跨条指代，名词重复就重复写。
- 一条一个事实，一行写完，多条事实用列表分行。
- 禁分号与折行，逗号、顿号后不把半句劈到下一行，围栏代码块与行内代码段除外。

## 标点

句号按载体，下表写行尾带不带：

| 载体 | 行尾 | 例 |
| :--- | :--- | :--- |
| docstring 标题与详情行 | 不带 | `- 标题与详情之间空一行` |
| 代码注释 | 不带 | `# 分组名` |
| 文档正文列表项 | 带 | `- 同一条判据只写在一处。` |
| commit 标题与正文要点 | 不带 | `- 撤掉版本检查按钮` |
| tag 附注摘要 | 不带 | `Release v0.1.0: 接口契约，领域词表` |
| CHANGELOG 条目 | 带 | `- **要点**：说明。` |
| release 正文条目 | 带 | `- 条目一。` |

- CHANGELOG 的纯主题行 `- **主题**：` 止于冒号，不带句号。
- release 正文的段名行与下载直链行不带句号。
- 分组引导词单独成行、以 `：` 收尾。
- 引用界面词一律半角双引号括起。
  - 屏上原话整句照抄，原话自带的「」留在引号里面，如 `"点「用内置模板覆盖」可直接换新"`。
- 代码标识用反引号括起，专有名词与单位裸写（GitHub、PySide6、KB/s）。
- 反引号不落进加粗主题行，要写标识就把说明放冒号之后。
- 中英文混排按 pangu spacing：中文与英文单词、数字之间补半角空格，全角标点紧贴中文不加空格，反引号内的代码原样保留、不拆空格。

## 条目与排版

- 列表前后各空一行，缩进子项紧贴父条目。
- 一个父条目只挂一条子项不算分层：同一件事缩成一行，两件事提上来当同级。
- 同一级条目不混排加粗主题：每条并列一个有名字的东西就全部带 `**主题**：`，纯规则列举就全部裸写。
- 加粗主题行不重复子项内容，单条能说完的不硬凑主题。
- commit 标题与正文之间空一行，正文逐行以 `- ` 起头，每行 72 字符内。
- release 正文标题行与列表之间空一行。
- docstring 标题与详情之间空一行，详情一律 `-` 起头，一行一个要点。
