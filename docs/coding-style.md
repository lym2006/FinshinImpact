# 代码规范

以 [`ruff.toml`](../ruff.toml) 管可机检项，本文管机器查不了的习惯。
扫描器按本文分节报违规，审过决定不改的待核登记在 [`devtools/style_waivers.toml`](../devtools/style_waivers.toml)，细则见 [style-checker.md](style-checker.md)。

## 文件骨架（自上而下）

```
# 路径注释 → 模块 docstring → 导入 → 常量 → 业务 → 主入口 → __main__
```

1. 首行相对路径 `# src/.../xx.py`，与文件名（含 `_` 前缀）严格一致。
2. 模块 docstring：一行定位 + 空行 + 短横列表说职责。
3. 禁用区块标题注释（`# === 对外暴露 ===`、`# === 辅助方法 ===` 一类）。
   - 六类分区由骨架顺序唯一确定：导入、全局常量与配置、对外暴露、核心业务逻辑、主程序入口、脚本直接运行入口。标题属噪音。
4. 一文件一主题，用文件名取代标题。
   - 函数太多或太长即拆子模块，分区语义写在文件名上。
5. 语义分组（字体域、表格域等读者需要横向定位的段落）用单行普通注释 `# 分组名`，不带等号横线。
6. 主入口永远在文件最底部，业务函数按调用者在上排列。
7. `__all__` 归属与门面最小导出见「命名与门面导出」。

## 拆分粒度

- 触发线，命中任一即拆：
  - 单文件超 300 行
  - 同族顶层函数超 5～6 个（同族按函数名首段词根判，`load_config` 与 `load_data` 同属 `load`）
  - 单类方法超 12 个
  - 单函数体超 60 行评审，80 行硬拆
- 下限：一个子模块至少两个同族成员。
  - 禁「一函数一文件」，例外仅门面 `__init__`、抽象 base、纯数据模型文件。
- 拆分按族走，一族放不下才开第二个文件。
- 只拆不合：触发线只要求移动代码，禁止顺手合并功能或加中间层凑数。
- 拆分只移动代码与改名，不改行为。
- 紧耦合豁免：方法间互传控件引用的 UI 行构建类，命中触发线也不拆（拆开即跨模块来回传引用）。
- 单文件行数超限不进豁免清单，只拆分或改扫描阈值，机制见 [style-checker.md](style-checker.md)。

## 分层职责

- 视图层只做三件事：收用户输入、调下层、把结果画出来。
- 判定与结算一律写在服务层，窗体模块里不写业务规则。
- 判据：同一条规则换个界面还要用，就必须下沉。
- 引导期窗体与主窗同为视图层，只消费服务层函数，不自己算。

## Docstring

标题行：

- 写简单定语加名词（`Bot 管理器`），或写简单动作（`网络探测`）。
- 不塞流程、不带标点。要带的解释降为一条 `-` 行，或写进代码注释，不许留在标题。
- 一行说得完就不开详情段。
- 状语能并成定语的就并（`实例锁占用探测（静默）` 写作 `实例锁占用静默探测`），并不动就不写。

详情段：

- 标题与详情之间空一行，一行一个要点，一律 `-` 起头。
- 只写做什么，不写它不依赖什么。
  - "不碰 UI""纯 stdlib""零副作用""只依赖 X""任何层可安全导入"一类架构自述句一律禁止，import 清单本身就是答案。
  - "唯一入口""唯一入参""唯一来源"同属自述，一并禁止。
- 具体实现与"为什么"下沉到函数体内的注释。
- 解释行为的散文不点名标识符、模块或文件路径（"供 settings 装配""被 gui 调用"），改名后悄悄失效。
- 要交代依赖波及面只写角色类别（"建钮处""各窗 QSS 选择器"）。

只写现状：

- 禁变更叙述与溯源："不再 X""此前 X""已改为 X""与 X 同源""沿用 X 的写法"一律删。
- 禁 roadmap："待落地""未来支持""留给 X 批次"写进 `docs/design/`，代码里不留。
- 禁背景解释：讲外部世界为什么麻烦的句子属"为什么"，下沉到它所解释的那行代码上方，详情行只留本函数产出什么。

措辞：

- 删修饰词与口语尾巴（"近乎零耗时""让类型契约名副其实""宁可 X 也不 Y""它们"），一个从句说得清就不加第二个，能删的限定词一律删。
- 一行一句，行尾不写句号。
- 禁分号：一条事实一行，用 `-` 分行。
- 禁折行：逗号、顿号后不许把半句劈到下一行，超长拆成短句。
- 措辞类违规 `Ruff` 与扫描器都查不出，交付前对改动文件 grep 一遍禁词兜底：`不再|此前|原本|沿用|同源|待落地|唯一入|不碰|耗时|敏感`。

## 注释

定义上方：

- 函数与类定义一律不加前置注释，说明由 docstring 与函数体内注释承担。
- 看似给多个定义分组的注释同样禁止（紧贴 def 时读者分不清它注哪一个）。
- 确需给一组定义分类，就拆成子类或子文件，或把说明写进各自 docstring。

写什么：

- 整行注释只允许两种：语义分组名（`# 字体域`）、代码内部的"为什么"。禁止区块标题与装饰横线。
- 变量与常量可加注释：标识符类写"改名会波及谁"，度量类写换算值，不复述命名本身。
- "改名会波及谁"写角色类别不写具体名（"各窗 QSS 选择器"），点名到模块或文件路径的散文改名即失效。
- `# 用：<路径>` 单源指针与「如 X」示例属有意引用，照常写。
- 过期注释按 bug 处理，改码必改注。

位置：

- 整行注释紧贴其描述的代码，中间不空行。
  - 紧贴即管辖，注释后面蹭着的代码一律视为归它管。
- 与注释无关的内容必须空一行隔开，免得读者误认注释也在说它。
- 两条整行注释之间不许空行分隔：分组名要么紧贴它领起的代码，要么删掉，说明交给紧贴代码的那条注释。
- 整行注释上方空一行，以下四处豁免：
  - 多行注释非首行
  - 块首（`:` `(` `[` `{` `,` 结尾）之后
  - docstring 之后
  - `__all__` 内部
- 行尾短尾注紧贴代码，与代码空两格、`#` 后空一格。`Ruff` 只保证这两条，不做列对齐，配置文件里的对齐注释要手工打散。
- 文档代码块里的说明另起一行，写在被说明的那行上方。必须写行尾注时按上条格式。

行文：

- 原则上单行，内容多就写多行，一行只说一个事实。
- 禁分号、折行（同「Docstring」）。

## 文档写法

- 一条一个事实，一行写完，禁分号与折行（同「Docstring」）。
- 分组引导词单独成行、以 `：` 收尾，与下面的列表之间空一行。
  - 列表前后各空一行，免得解析器把首条当成上一句的续行。
  - 条目下的缩进子项紧贴父条目，不空行。
- 同一条判据只写在一处，别处写引用（如「见 [style-checker.md](style-checker.md)」），不复述。
- 禁用「前者/后者/此类」跨条指代，要读者倒回上一条才找得到指谁，就等于没写。
- 文档同时给人和接手改动的 AI 工具读：路径与符号名写全、当场可 grep，不写行号与临时产物。

## 导入

- 同顶层包内一律相对，跨顶层包与第三方、标准库一律绝对。
- 相对点数按目标模块相对当前模块的真实层级写：兄弟子包 `..`，再往外逐层递增。
- 子包不得从父包门面取符号（`from .. import x`），要引就引到具体兄弟模块。
- 父包 `__init__` 只作命名空间与对外汇总，别处定义的符号不许绕道从它取。
- 包内互用走相对直连，不绕自家门面，防循环依赖回流。
- 包的主角类定义在具体子模块里，门面只代发，包内不必反向取它。
- 类确实定义在门面里时，包内模块反向取它只能走 `from . import X`，且必须留在 `TYPE_CHECKING` 块内。

## 命名与门面导出

| 对象 | 规则 | 例 |
| :--- | :--- | :--- |
| 包内实现文件 / 目录 | `_` 前缀 | `_connectivity.py` |
| 对外文件 / 目录 | 无前缀 | `lifecycle.py` |
| 模块私有常量 | 大写 + `_` 前缀 | `_MAX_RETRIES` |
| 对外导出常量 | 裸大写 | `LOGS_DIR` |
| 私有类型别名 | `_` 前缀 | `_FontType` |
| 函数 / 变量 | snake_case，私有加 `_` | `_apply_update` |
| 类 | PascalCase，私有加 `_` | `_Holder` |

- 私有内容标记 `_` 前缀后不额外写「内部实现」标注。
- "对外"唯一标准：进 `__all__` 或被其他模块 import，否则一律 `_` 前缀。文件、目录、类、方法、变量、常量一律适用。
- 消费方只算 `src` 侧调用，devtools 的引用不把 `src` 符号算成对外，机制见 [style-checker.md](style-checker.md)。
- 仅由包门面 `__init__.py` 导入的子模块属内部实现，文件名加 `_` 前缀。
- `__all__` 只属于非空门面：代发多消费方符号的包 `__init__.py` 才写，且必写。
- 业务模块与纯转发门面不写 `__all__`，消费方直连子模块导入。本地需要私有名时 `import symbol as _symbol`。
- 门面最小导出：包门面只代发多消费方符号。
  - 单一或极少数消费者的符号不进门面，子模块转正（去 `_` 前缀），由调用方 `from package.module import symbol` 直连。
- `__all__` 按含义分组，不按字母序。
  - 组前一行 `# 组名`，成员紧贴其下，遵守「注释」节的紧贴规则。
  - 分组顺序与文件内定义顺序对应，读者能对着看。
- `__all__` 只有一项时豁免分组注释，直接裸写（如 `main`、`Main` 这类单一入口）。
- 同源的散装模块级变量（常量、配置项、协议串）攒够三五件即收进命名空间类，不许裸变量持续堆积。
- `core/dto` 类型一律 `DTO` 后缀（如 `PrincipalDTO`、`MsgReferenceDTO`）。
- 词表按变更范围归层：与某 DTO 字段共变的进该 DTO 文件，横切适配层与存储的进 `core/domain`。
- 同域成员不重复域前缀：类名或裸常量前缀已表达域义，成员只写语义本体。
  - `RowStatus.SKIP` 不写成 `ROW_STATUS_SKIP`，`CheckMessage.TIMEOUT` 不写成 `_CHECK_TIMEOUT`。
- 域与域靠语义区分，命名格式全文件一致。
  - 域外可见的裸常量一律 `DOMAIN_MEANING[_UNIT]`（如 `PUSH_MAX_RETRIES`、`CONNECT_TIMEOUT_MS`），私有加 `_` 前缀（如 `_PUSH_MAX_RETRIES`），禁止混用其他样式。

## 魔法数字与字符串

- 提为文件顶部私有常量，命名带单位语义，行尾注释换算值。
- 常量归属分两类：
  - 标识符类（文件名、目录名、字典键名、协议串）：各方必须取同一个值，单源一处定义，消费方直连引用，重复定义按 bug 处理。
  - 度量类（超时、尺寸、阈值）：数值相等不构成同一契约，谁用谁持有，禁止为数值巧合抽公共常量。
- 协议串（状态机等跨模块比较的短字符串）收进命名空间类（如 `RowStatus`），比较侧引用类属性，禁止裸写。

## 枚举

- 枚举基类只准 `StrEnum` 与 `IntEnum`，禁裸 `Enum`。
  - 成员值即落盘值、即比较值，一份字面量贯穿代码、配置与库。
- 判定一律 `==` 比成员：禁裸 `Enum` 成员入参、禁 `.value` 取值、禁 `is` 比成员。
  - 成员可直接参与 `in` 容器、`join`、f-string、`json.dumps`、SQLite 绑定、tomlkit 落盘、`setObjectName`，都不必先取 `.value`。
- `IntEnum` 成员与裸整数本就 `==` 比中，裸数字失去分支语义，比较与赋值处一律写成员。
- 参与大小比较（排序、阈值）的枚举写死数字并留间隔（0/10/50），禁 `auto()`。
  - 间隔是给以后插档留位。
  - 写死的号同时就是 `plugin.toml` 与 `task` 表的落盘格式，改成 `auto()` 现成清单当场读不回。
- 纯分支标识（只判相等、不比大小）可用 `auto()`。
- 成员值必须互不相等且随定义顺序严格递增，重号即静默别名。
  - 同值两成员会被 `{...}` 成员集静默收下，`==` 照样比中。
  - `IntEnum` 由 devtools 扫描器按此查。
- `StrEnum` 成员值是用户可见文案或对方规定的字段名，改值等于改用户看到的字，不许顺手改。

## 日志与文案

- 面板只记状态推进，单行短句。
  - 多行结构化信息只走弹窗，明细降 `DEBUG` 落文件，面板不重复灌入。
- 级别只用 `DEBUG` / `INFO` / `ERROR`。
  - 格式器列宽 `%(levelname)-5s` 按五字符定死，`WARNING`、`CRITICAL` 顶宽会把消息列整体推歪。
  - 要加级别先保证名字不超五字符，且同步复核面板最小宽度。
- 弹窗文案高度随行数自适应撑开，不靠空首行土办法。
- 文案收敛：
  - `GUI` 可见文案收敛进 `skin/messages/`，禁止 f-string 裸写业务话术。
  - `Bot` 对话话术收敛进 `src/plugins/messages.py`（`BotMessage`），插件间直连引用，禁止内联裸写。
  - 运行日志不属对话文案，不收敛，就地内联保持可 grep。
  - 异常文案模板在同文件就近写映射表。
  - `theme` 令牌只代理引用、不持有话术字面量。

## 文案类（skin/messages/）

- 每域一个类 `XxxMessage`。
- 域文件仅门面导入属内部实现，文件名带 `_` 且为类名 snake_case（`CheckMessage` ↔ `_check.py`）
- 类名已含域义则成员不再重复域前缀（同「命名与门面导出」）。
- 跨域同义文案单源一处定义，另一域直接引用，禁止字面复制。
- 每条成员行首注释标注使用位置。

## 回调形参

- 框架回调的形参名与位置由框架的绑定方式决定，先分清两种绑定再定名字。
- 按位置注入的对象（aiogram 的原始 `Message`）：位子在首位、不可省略、名字随项目定。
  - 全项目统一叫 `raw`，禁用 `message` 与占位 `_`。
  - 协程形参由扫描器按此查，判据见 [style-checker.md](style-checker.md)。
- 按参数名注入的对象（`ctx`、`bot`）：名字即契约，改了注入不到。
  - 按名注入的形参排在事件之后，位置传参和关键字传参都行。
- 业务只读归一后的事件对象，`raw` 不参与判定与取值。缺它即绑不上事件，故不许删。
- 中间件 `__call__(handler, event, data)` 由框架全位置调用，不加 `*`、不改名。
- 加 `*` 的判据是错位风险，不是参数身份。
  - 可选参数与同型可互换参数用 `*` 隔开（`TelegramAdapter(token, *, proxy=None)` 两个都是 `str`）。
  - 必填且异型的参数按位置写。
- 判定类函数（`Filter.__call__`）的注入参数带 `| None` 默认值，未注入时返回 `False` 让路由继续，不抛错。

## 类型注解

- 所有 `def`（含方法）的形参与返回值一律写注解，`__init__` 返回 `-> None`。
- 局部变量类型不自明时补声明注解。
- 仅三类情况允许 `# type: ignore`，无需在行尾注明原因：
  - 不必要的注解：`self` / `cls`、简单 lambda。
  - 循环导入：正向引用先 `TYPE_CHECKING` + 字符串注解，仍解不出的才 ignore。
  - 对齐官方方法：重写 Qt / 三方基类回调（`closeEvent` 等），基类签名本身无提示。
- `super().__init__(*args, **kwargs)` 这类纯转发不为注解引入 `ParamSpec`。
  - 能收口的写显式签名，收口不了的按上述豁免。
- `# type: ignore` 一律带 `[具体错误码]`，裸 ignore 会把整行其他错误一起吞掉。devtools 扫描器按此查。
