# 代码规范

可机检项见 [ruff.toml](../ruff.toml)，本文规定代码与文档写法。
扫描器机制与豁免清单见 [style-checker.md](style-checker.md)。

## 文件骨架（自上而下）

```
模块 docstring → 导入 → 常量 → 业务 → 主入口 → __main__
```

1. 首行是模块 docstring，文件里不写路径注释。
2. 模块 docstring：一行定位 + 空行 + 短横列表说职责。
3. 禁用区块标题注释（`# === 对外暴露 ===`、`# === 辅助方法 ===` 一类），分区由骨架顺序唯一确定：导入、全局常量与配置、对外暴露、核心业务逻辑、主程序入口、脚本直接运行入口。
4. 一文件一主题，用文件名取代标题。函数太多或太长即拆子模块，分区语义写在文件名上。
5. 语义分组（字体域、表格域等读者需要横向定位的段落）用单行普通注释 `# 分组名`，不带等号横线。
6. 主入口永远在文件最底部，业务函数按调用者在上排列。

## 拆分粒度

- 触发线，命中任一即拆：
  - 单文件超 300 行
  - 同族顶层函数超 5～6 个（同族按函数名首段词根判）
  - 单类方法超 12 个
  - 单函数体超 60 行评审，80 行硬拆
- 下限：一个子模块至少两个同族成员。
- 禁「一函数一文件」，例外仅门面 `__init__`、抽象 base、纯数据模型文件。
- 拆分按族走，一族放不下才开第二个文件。
- 只拆不合：触发线只要求移动代码与改名，不改行为，禁止顺手合并功能或加中间层凑数。
- 紧耦合豁免：方法间互传控件引用的 UI 行构建类，命中触发线也不拆。
- 豁免范围见 [style-checker.md](style-checker.md) 的「待核豁免清单」节。

## 复用优先

- 写新东西之前先查已有：按四类现搜一遍——读同类文件、算同类值、拼同类串、画同类界面
- 同一逻辑两处出现即抽公共件，相同的部分一律抽，不同处用传参或其他入口分开，只有硬限制或两侧确实不同才各写一份
- 公共件的落点按「分层职责」定，命名与导出按「命名与门面导出」定
- 跨打包边界引不到的两侧各留一份，注释点名与哪一侧同值，改名两处一起

## 分层职责

- 视图层只做三件事：收用户输入、调下层、把结果画出来。
- 判定与结算一律写在服务层，窗体模块里不写业务规则。
- 判据：同一条规则换个界面还要用，就必须下沉。
- 引导期窗体与主窗同为视图层，只消费服务层函数，不自己算。
- 代发平台要实现的两份抽象接口只从 `finshin_sdk` 取，本体不直接引适配器。
- 平台框架（aiogram）只许适配器引。
- 外部插件与适配器只准引接口包。
- 分层与隔离的成文判据以 `.importlinter` 为准，本节只写职责与方向，不逐条抄契约名。
- 接口包对外只代发插件与适配器真要用的那几样，没人用的形状留在本体侧，别放上对外那一面。

## Docstring

标题行：

- 写简单定语加名词（`Bot 管理器`），或写简单动作（`网络探测`）。
- 不塞流程、不带标点。
- 要带的解释降为一条 `-` 行，或写进代码注释，不许留在标题。
- 一行说得完就不开详情段。
- 状语能并成定语的就并，并不动就不写。

详情段：

- 标题与详情之间空一行，一行一个要点，一律 `-` 起头。
- 纯定义件（只装枚举、常量、键名表、数据结构与抽象接口的件）的模块级详情行以「定义 」起头，逐条列这一份装了哪些词表与结构。
- 带行为的件与包门面直写动作或名词，不套「定义」「实现」「提供」壳。
- 只写做什么。
  - 「不碰 UI」「纯 stdlib」「零副作用」「只依赖 X」「任何层可安全导入」一类架构自述句一律禁止。
  - 「唯一入口」「唯一入参」「唯一来源」同属自述，一并禁止。
- 具体实现与「为什么」下沉到函数体内的注释。
- 解释行为的散文不点名标识符、模块或文件路径（「供 settings 装配」「被 gui 调用」）。
- 要交代依赖波及面只写角色类别（「建钮处」「各窗 QSS 选择器」）。

只写现状：

- 禁变更叙述与溯源：「不再 X」「此前 X」「已改为 X」「与 X 同源」「沿用 X 的写法」一律删。
- 禁 roadmap：「待落地」「未来支持」「留给 X 批次」这类话不进代码。
- 禁背景解释：讲外部世界为什么麻烦的句子属「为什么」，下沉到它所解释的那行代码上方，详情行只留本函数产出什么。

措辞：

- 中文措辞、分行与标点见「文档写法」节。
- 详情行行尾不写句号。
- 措辞类违规 `Ruff` 与扫描器都查不出，交付前对改动文件 grep 一遍禁词兜底：`不再|此前|原本|沿用|同源|待落地|唯一入|不碰|耗时|敏感`。

## 注释

定义上方：

- 函数与类定义一律不加前置注释，看似给多个定义分组的注释同样禁止，说明由 docstring 与函数体内注释承担。
- 确需给一组定义分类，就拆成子类或子文件，或把说明写进各自 docstring。

写什么：

- 整行注释只允许两种：语义分组名（`# 字体域`）、代码内部的「为什么」。
- 禁止区块标题与装饰横线。
- 变量与常量可加注释：标识符类写「改名会波及谁」，度量类写换算值，不复述命名本身。
- `# 用：<路径>` 单源指针与「如 X」示例属有意引用，照常写。
- 过期注释按 bug 处理，改码必改注。

位置：

- 整行注释紧贴其描述的代码，中间不空行。
- 紧贴即管辖，注释后面蹭着的代码一律视为归它管。
- 两条整行注释之间不许空行分隔：分组名要么紧贴它领起的代码，要么删掉，说明交给紧贴代码的那条注释。
- 整行注释上方空一行，以下几处豁免：
  - 多行注释非首行
  - 块首（`:` `(` `[` `{` `,` 结尾）之后
  - docstring 之后
  - `__all__` 内部
- 行尾短尾注紧贴代码，与代码空两格、`#` 后空一格，文档代码块里同样。
- 配置文件里的对齐注释要手工打散。
- 文档代码块里的说明另起一行，写在被说明的那行上方。

行文：

中文措辞、分行与标点见「文档写法」节。

## 文档写法

### 内容归属

- 规范正文只写规矩与判据，要留的理由写成指针，如「理由见 [lessons/layering.md](lessons/layering.md)」。
- 经验的收录范围见 [lessons/README.md](lessons/README.md)。
- 理由与过程的工作底稿不进版本库，按各自口径写。
- 发布文档不写内部待办、批次编号、对话过程与只在一台机器上成立的叙述，不链接不进版本库的目录。
- 同一条判据只写在一处，别处只指向文件与节名，如「见 [style-checker.md](style-checker.md) 的「跑法」节」。
- 旧版迁移按受众分工：
  - 用户要不要动手与动手步骤写进 [README.md](../README.md)。
  - 逐项改法写进 [development.md](development.md)。
  - 改了什么与影响到谁记进 [CHANGELOG.md](../CHANGELOG.md)。
- 对每只子仓都成立的规矩与指路写主仓，只对某一只成立的才写它自己的 README。
- 路径与符号名写全、当场可 grep，不写行号与临时产物。
- md 相对链接指向的文件必须当场存在。

### 中文措辞

以下写法适用于 docstring、代码注释与文档正文：

- 写人话，不自造术语与内部简称，要指什么就写那件事本身。
- 删修饰、比喻、连接性废话与口语尾巴，不堆书面腔也不刻意口语。
- 一个从句说得清就不加第二个，能删的限定词一律删。
- 不拿 `＝` 与 `=` 代替「就是」，代码与命令行里的语法照旧。
- 一条一个事实，一行写完，多条事实用列表分行。
- 禁分号与折行，逗号、顿号后不把半句劈到下一行。
- 分号判据不覆盖围栏代码块与行内代码段。
- 禁用「前者/后者/此类」跨条指代，名词重复就重复写。

### 条目与排版

- 分组引导词单独成行、以 `：` 收尾。
- 列表前后各空一行，缩进子项紧贴父条目。
- 一个父条目只挂一条子项不算分层：同一件事缩成一行，两件事提上来当同级。
- 同一级条目不混排加粗主题，每条并列一个有名字的东西就全部带 `**主题**：`，纯规则列举就全部裸写。
- 引用界面词一律半角双引号括起。
- 屏上原话整句照抄，原话自带的方括号留在引号里面，如 `"点「用内置模板覆盖」可直接换新"`。
- 代码标识用反引号括起，专有名词与单位裸写（GitHub、PySide6、KB/s）。
- 中英文混排按 pangu spacing：中文与英文单词、数字之间补半角空格，全角标点紧贴中文不加空格，反引号内的代码原样保留、不拆空格。

## 导入

- 同顶层包内一律相对，跨顶层包与第三方、标准库一律绝对。
- 相对点数按目标模块相对当前模块的真实层级写。
- 子包不得从父包门面取符号（`from .. import x`），要引就引到具体兄弟模块。
- 父包 `__init__` 只作命名空间与对外汇总，包内互用走相对直连，别处定义的符号不许绕道从它取。
- 包的主角类定义在具体子模块里，门面只代发，包内不必反向取它。
- 类确实定义在门面里时，包内模块反向取它只能走 `from . import X`，且必须留在 `TYPE_CHECKING` 块内。

## 命名与门面导出

| 对象 | 规则 | 例 |
| :--- | :--- | :--- |
| 包内实现文件 / 目录 | `_` 前缀 | `_normalize.py` |
| 对外文件 / 目录 | 无前缀 | `lifecycle.py` |
| 模块私有常量 | 大写 + `_` 前缀 | `_MAX_RETRIES` |
| 对外导出常量 | 裸大写 | `LOGS_DIR` |
| 私有类型别名 | `_` 前缀 | `_FontType` |
| 函数 / 变量 | snake_case，私有加 `_` | `_apply_update` |
| 类 | PascalCase，私有加 `_` | `_Holder` |

- 私有内容标记 `_` 前缀后不额外写「内部实现」标注。
- 「对外」唯一标准（文件、目录、类、方法、变量、常量都适用）：进 `__all__` 或被其他模块 import，否则一律 `_` 前缀。
- `src` 符号的消费方只算 `src` 侧调用，devtools 的引用不把它算成对外。
- devtools 允许直连 `src` 的内部实现，devtools 内部互用仍按命名与导入规则检查。
- 仅由包门面 `__init__.py` 导入的子模块属内部实现，文件名加 `_` 前缀。
- `__all__` 只属于非空门面：代发多消费方符号的包 `__init__.py` 才写，且必写。
- 业务模块与纯转发门面不写 `__all__`，消费方直连子模块导入。
- 本地需要私有名时 `import symbol as _symbol`。
- 单一或极少数消费者的符号不进门面，子模块转正（去 `_` 前缀），由调用方 `from package.module import symbol` 直连。
- `__all__` 按含义分组，不按字母序。
  - 组前一行 `# 组名`，成员紧贴其下，遵守「注释」节的紧贴规则。
  - 分组顺序与文件内定义顺序对应，读者能对着看。
- `__all__` 只有一项时豁免分组注释，直接裸写（如 `main`、`Main` 这类单一入口）。
- 同源的散装模块级变量（常量、配置项、协议串）攒够三五件即收进命名空间类，不许裸变量持续堆积。
- 接口包 `finshin_sdk/dto` 类型一律 `DTO` 后缀（如 `PrincipalDTO`、`MsgReferenceDTO`）。
- 类型后缀分三类：类型定义 `XxxType`，定位与寻址 `XxxKey`，身份 `XxxId`。
- 语义冲突时优先保语义正确，枚举惯用后缀照旧保留（`Kind`、`Mode`、`Status`、`Role`、`Scope`、`Priority`、`Flag`、`Path`、`Spec`、`Schema`、`Callback`、`Result`），不为三类硬改成 `Type`。
- 词根贯通：表达同一概念的属性、形参、局部缩写变量同批改名。
- 两个概念只在有映射关系的那一处换算，不硬并。
- 跨 DTO 复用的语义串集中到领域层的标识模块，消费者从那里 import。
- 词表按变更范围归层：与某 DTO 字段共变的进该 DTO 文件，横切适配层与存储的进接口包的领域层 `finshin_sdk/domain`。
- 同域成员不重复域前缀：类名或裸常量前缀已表达域义，成员只写语义本体。
- 域外可见的裸常量一律 `DOMAIN_MEANING[_UNIT]`（如 `PUSH_MAX_RETRIES`、`CONNECT_TIMEOUT_MS`），私有加 `_` 前缀（如 `_PUSH_MAX_RETRIES`），域与域靠语义区分，命名格式全文件一致。

## 魔法数字与字符串

- 提为文件顶部私有常量，命名带单位语义，行尾注释换算值。
- 常量归属分两类：
  - 标识符类（文件名、目录名、字典键名、协议串）：各方必须取同一个值，单源一处定义，消费方直连引用，重复定义按 bug 处理。
  - 度量类（超时、尺寸、阈值）：数值相等不构成同一契约，谁用谁持有，禁止为数值巧合抽公共常量。
- 协议串（状态机等跨模块比较的短字符串）收进命名空间类（如 `RowStatus`），比较侧引用类属性，禁止裸写。
- 在线地址与协议头只写在地址的家那几份文件里：
  - 本体侧 `system/links.py`，启动器侧 `pack_spec.py`，构建原料的成套地址随原料清单那份件，端点默认值随该配置项。
  - 文案里的示例地址属文案那侧，用例夹具里的假地址属用例那侧。
  - 家清单在扫描器里按路径片段写死，新增家要两处一起改，家外裸写按硬性报。

## 枚举

- 枚举基类只准 `StrEnum` 与 `IntEnum`。
- 成员值即落盘值、即比较值，一份字面量贯穿代码、配置与库。
- 判定一律 `==` 比成员，成员可直接参与 `in` 容器、`join`、f-string、`json.dumps`、SQLite 绑定、配置文件落盘、`setObjectName`，都不必先取 `.value`。
- 函数形参禁裸 `Enum` 成员。
- `IntEnum` 成员与裸整数本就 `==` 比中，裸数字失去分支语义，比较与赋值处一律写成员。
- 参与大小比较（排序、阈值）的枚举写死数字并留间隔（0/10/50），禁 `auto()`，理由见 [lessons/layering.md](lessons/layering.md)。
- 纯分支标识（只判相等、不比大小）可用 `auto()`。
- 成员值必须互不相等且随定义顺序严格递增，`StrEnum` 成员值是用户可见文案或对方规定的字段名，不许顺手改。

## 日志与文案

- 面板只记状态推进，单行短句。
- 多行结构化信息只走弹窗，明细降 `DEBUG` 落文件，面板不重复灌入。
- 级别只用 `DEBUG` / `INFO` / `ERROR`，要加级别先保证名字不超五字符，且同步复核面板最小宽度，理由见 [lessons/gui-and-styles.md](lessons/gui-and-styles.md)。
- 日志消息串就地用 f-string 组好，不许留 `%s` 占位再往后传参，理由见 [lessons/tooling-false-green.md](lessons/tooling-false-green.md)。
- 弹窗文案高度随行数自适应撑开，不靠空首行土办法。
- 配置项在 `FieldSpec` 里定了 `bounds` 的，界值要写进输入框下面的说明文案，形状统一 `取值范围 X~Y，…`。
- 文案收敛：
  - `GUI` 可见文案收敛进 `skin/messages/`，禁止 f-string 裸写业务话术。
  - `Bot` 对话话术收敛进 `src/bundled/_shared/messages.py`（`BotMessage`），插件间直连引用，禁止内联裸写。
  - 运行日志不属对话文案，不收敛，就地内联保持可 grep。
  - 异常文案模板在同文件就近写映射表，取文案一律走 `exceptions.describe_error`，调用处不自行查表填参。
  - 异常类定义在接口包时，映射表仍写在本体侧同族的文件里，表键直接引那只类，句子不外发。
  - `theme` 令牌只代理引用、不持有话术字面量。
- 兜底一律走 `utils/error_guard.py` 那一只公共件，默认只接本族异常（`BotError` 一族），普通异常照穿。
- 要全兜在调用处点名，不改默认值，理由见 [lessons/layering.md](lessons/layering.md)。

## 文案类（skin/messages/）

- 每域一个类 `XxxMessage`。
- 域文件仅门面导入属内部实现，文件名带 `_` 且为类名 snake_case（`CheckMessage` ↔ `_check.py`）
- 跨域同义文案单源一处定义，另一域直接引用，禁止字面复制。
- 每条成员行首注释标注使用位置。

## 回调形参

- 框架回调的形参名与位置由框架的绑定方式决定，先分清两种绑定再定名字。
- 按位置注入的原始事件排在首位，不可省略。
- 原始事件在适配层内叫 `raw` 并标注平台类型。
- 原始事件在适配层之外叫 `platform_raw` 且注解只写 `object`。
- 原始事件形参禁用 `message` 与占位 `_`。
- 按参数名注入的对象（`ctx`、`bot`）：名字即契约，改了注入不到，框架回调中注解为 `HandlerContext` 的形参叫 `ctx`。
- 按名注入的形参排在事件之后，位置传参和关键字传参都行。
- 业务只读归一后的事件对象，`platform_raw` 不参与判定与取值，不许删。
- 可选参数与同型可互换参数用 `*` 隔开（`TelegramAdapter(token, *, proxy=None)` 两个都是 `str`）。
- 必填且异型的参数按位置写。
- 判定类函数（`Filter.__call__`）的注入参数带 `| None` 默认值，未注入时返回 `False` 让路由继续，不抛错。

## 类型注解

- 所有 `def`（含方法）的形参与返回值一律写注解，`__init__` 返回 `-> None`。
- 局部变量类型不自明时补声明注解。
- 仅三类情况允许 `# type: ignore`，无需在行尾注明原因：
  - 不必要的注解：`self` / `cls`、简单 lambda。
  - 循环导入：正向引用先 `TYPE_CHECKING` + 字符串注解，仍解不出的才 ignore。
  - 对齐官方方法：重写 Qt / 三方基类回调（`closeEvent` 等），基类签名本身无提示。
- `super().__init__(*args, **kwargs)` 这类纯转发不为注解引入 `ParamSpec`。
- 能收口的写显式签名，收口不了的按上面三类豁免。
- `# type: ignore` 一律带 `[具体错误码]`，devtools 扫描器按此查，理由见 [lessons/tooling-false-green.md](lessons/tooling-false-green.md)。

## 按钮样式

- 一颗按钮只由三样东西决定：词、档、回调。词取 `skin/theme/_buttons.py` 的 `ButtonStyle`，档取同文件的 `ButtonSize`，对象名由 `button_object_name` 算出，构造统一走 `make_button`。
- 调用点只传词、档与回调，不写颜色、内边距、最小宽。
- 按钮样式规则唯一出处在 `src/skin/qss/_buttons.py`，各窗经 `build_button_qss()` 取得，其余 qss 文件不出现 `QPushButton` 规则。
- 规则按「词×档」的实际组合生成，组合数固定，窗数增加不增加规则段。
