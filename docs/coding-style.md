# 代码规范

本项目代码风格以 [`docs/example.py`](example.py) 为唯一模板，`ruff.toml` 负责可机检的部分，本文档记录机器查不了的习惯。改代码前先通读模板骨架。

## 文件骨架（自上而下）

```
# 路径注释 → 模块 docstring → 导入 → 常量 → __all__ → 业务 → 主入口 → __main__
```

1. 首行 `# 相对路径.py`，标明文件在仓库中的位置。
2. 模块 docstring：一行定位 + 空行 + 短横列表说职责。
3. 区块标题注释（见下节）划分区域，顺序固定：导入 → 全局常量与配置 → 对外暴露 → 核心业务逻辑 → 主程序入口 → 脚本直接运行入口。
4. 主入口函数永远放在文件最底部，业务函数按自顶向下的阅读顺序排列（调用者在调用者上面）。

## 区块标题注释

```python
# ==================== 核心业务逻辑 ====================
```

- 等号固定 20 个，标题不带序号、不带标点、不加尾随空格。
- 上下各留一个空行（区块内第一条定义与标题之间为空两行的标准间隔由 ruff 管）。
- 只在文件宏观分区使用；函数内部的步骤说明用行内注释，不许造新区块。

## Docstring

- 第一行：短定位语（名词或单动作，如 `启动器换壳`、`信息弹窗`），**不把流程塞进标题**。
- 标题与详情之间必须空一行。
- 详情段写完整行为、"为什么"与约定。
- 单行能说完的不硬凑空行详情；琐碎操作留给行内注释。

```python
def _apply_shell_update(root: Path) -> None:
    """启动器换壳

    旧 exe 改名让位，暂存的新壳放入原位后立即重启。
    自我改名后本进程句柄仍跟着旧文件走，原位放入新壳重启即完成更换。
    """
```

## 注释

- 行内注释说"为什么"，不复述代码在"做什么"。
- 允许在成组赋值、非常规调用后挂短尾注（如 `# 拉起新壳`）。
- 中文书写，与代码之间空两格。
- 过期注释按 bug 处理，改码必改注。

## 命名

| 对象 | 规则 | 例 |
| :--- | :--- | :--- |
| 模块私有常量 | 大写 + `_` 前缀 | `_MAX_RETRIES` |
| 对外导出的常量/API | 裸大写，无前缀 | `LOGS_DIR` |
| 私有类型别名 | `_` 前缀 | `_FontType` |
| 模块级临时变量 | 小写 + `_` 前缀 | `_var` |
| 函数 / 变量 | snake_case | `_apply_update` |
| 类 | PascalCase | 私有类同样 `_` 前缀 |

判定"对外"的唯一标准：是否进 `__all__` 或被其他模块 import。只要没被外部引用，就是私有，必须加 `_`。

## 魔法数字

- 一律提为文件顶部私有常量，命名带单位语义：`_DOWNLOAD_TIMEOUT`、`_BYTES_PER_MB`。
- 常量行尾注释标注换算值：`_REQUEST_TIMEOUT = 10.0  # 版本页请求超时 10 秒`。
- 跨模块共用的数值放进公共 utils 并以裸大写导出，禁止两处重复定义（如 `LOGS_DIR`）。

## 其他硬约定

- 日志等级只用 `INFO` / `ERROR` / `DEBUG` 三级，新增等级须先改本文档。
- 用户可见文案集中在 `src/plugins/messages.py` 或主题配置，业务代码不硬编码话术。
